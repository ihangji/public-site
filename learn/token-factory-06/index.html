6.1 分工由来

海外推理项目最容易产生的错觉，是把认识上游、手里有卡、能部署模型、接触客户听成同一家公司拥有端到端能力。现实中，资产、运行、产品和交易通常分散在不同主体，一个参与者可以很强，却只控制其中一层。

分工的根源是时间尺度不同：芯片按代际迭代，机房按年建设和出租，服务按秒处理请求，合同按月或多年结算，基金与债务又有自己的到期日，没有单一组织天然适合同时管理所有时钟。分工降低了每个角色的进入成本，也增加了接口成本：延迟上升时，客户可能不知道是模型、路由、GPU、网络还是上游限流出了问题，每个参与者也有动机把故障推向自己合同之外。

6.2 四层角色

资产层：芯片厂、整机厂、服务器所有人、出租人、机房和电力网络运营商构成物理底座，收入来自设备销售、租金、机柜、电力和端口。Equinix 的年报把空间、电力、互联与托管作为核心产品，Digital Realty 披露大型电力容量租约常见 5 到 10 年或更久。核这一层拥有重资产和长合同，主要风险是建设交付、电力、技术过时、残值和承租人信用；它保证机器有地方运行，不保证某个模型满足 API 延迟。

运行层：AI 云、GPU 云、集群运营方、推理引擎与运维团队把硬件变成可调度资源，控制驱动、容器、镜像、模型部署、批处理、路由、监控和故障恢复。运行层的核心资产有时不是机器，而是技术控制面：谁能上架模型、分配 GPU、调整并发、回滚版本、查看端到端遥测。只有监控没有执行权，不构成运营控制。

产品层：模型所有人、MaaS 平台、专用端点提供方和聚合路由把技术能力包装成客户可购买的产品，决定模型目录、API 兼容、计量、限流、区域、版本和价格。聚合器最容易被误认成供给所有人：OpenRouter 的公开机制显示它按故障、价格、吞吐与延迟在多个供应商间路由，按实际 token 用量与供应商结算，它掌握客户入口、用量数据和统一账单，却不一定拥有底层 GPU 或模型。核其优势是需求聚合与切换，风险是上游依赖、数据路径和责任链变长。

交易层：企业客户、应用开发者、渠道、付款与税务主体、贷款人、LP、GP 和 SPV 决定谁签约、谁付款、谁融资、谁承担损失。交易层不是技术完成后的行政尾巴，它规定什么结果可验收、什么故障算违约、什么用量能开票。

6.3 控制四列

分析任何资源，都把四种关系拆开看。

  • 法律所有权　资产或模型权利属于谁
  • 合同控制　谁能出租、转售、承诺期限、调价和终止
  • 技术控制　谁能配置、监控、调度、停机和恢复
  • 运营责任　出了问题谁必须在什么时间采取行动

这四列是全书的控制权主词典。第 7 章加上产品边界，第 31 章加上跨境位置，第 30 章加上融资与担保，都不改变这个区分。

一台 GPU 可以属于融资 SPV，由运营方租用，放在第三方机房，受云平台控制面调度，最终服务另一个主体签下的客户。此时我们的卡这四个字至少有四种含义，没有逐列回答之前，任何拥有多少资源的说法都不能直接进入产能或收入模型。模型也一样：开源可下载不代表任何用途都不受许可证约束，获得 API 访问不等于获得权重，能部署权重不等于有权跨地区转售。

6.5 客户分层

客户也分五种：自助开发者看重低门槛、多模型和按量；成长期应用看重弹性和成本护栏；稳定企业负载看重隔离、版本、审计与 SLA；大型模型实验室或平台看重长期容量、价格和定制交付；渠道或聚合器看重转售权、统一计量和供应连续性。把所有客户都写成有 token 需求，会丢掉最重要的信息：相同月用量，突发程度、数据要求、模型切换和承诺期限不同，适配的产品和风险承担者也不同。

6.6 替代判断

判断一位参与者是否不可替代，不要问他认识谁，问他控制哪个稀缺接口，以及替换成本是什么。可验证的接口包括：独家或长期资产权、真实的集群管理员权限、模型许可证、可审计的客户合同、稳定回款、生产遥测、跨区域网络与本地运维。某一角色控制稀缺接口后能拿到一部分收入，其他参与者也会围绕该接口调整结构：渠道掌握大客户后，运营方可能接受更低毛利换长期承诺；运营方掌握稀缺容量后，客户可能预付并接受更严格的退出条件。控制权决定议价，不是职位名称决定议价。

行业地图有了，下一步看交付。一批裸算力要走到可以签合同、开发票，中间还有哪些状态和责任没有补齐？

追问对方自称有卡有客户有技术时，逐项问：法律所有权、合同控制、技术控制、运营责任各落在谁身上；他控制的稀缺接口是哪一个，换掉他要多少成本。
