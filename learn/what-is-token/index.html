Token 是什么

AI 扫盲约 8 分钟更新于 2026-08-04

为什么你要懂这个

商务在跟客户谈模型 API 服务的价格时，对方报价是"每百万 token 多少钱"。如果不知道 token 是什么，就换算不出客户每问一句话，我们要花多少钱、该收多少钱。月底拿到上游账单，上面只写消耗了几百万 token，你也没法判断数字对不对。报价、对账、容量规划三件事都用同一个单位，不懂它，这三件事都做不了。

一句话说清

模型处理文本的最小计费单位，一个 token 大约对应一个汉字。

打个比方

把 token 想成出租车的里程表。你让 AI 写一段话，模型是一个小块一个小块地"吐"出来的，每吐一小块，里程表走一格，最后按里程数结账。不同出租车公司（不同模型）每公里收费不一样，起步价和夜间价也可能不同（对应输入和输出分开计价）。

这个比方哪里不成立：出租车里程是客观的，同一个路段谁来开都一样长；token 数没有这个客观性，同一句话交给不同模型切分，数出来的 token 数量可能差不少。另外出租车空车等红灯不跳表，AI 服务即使部分内容命中了缓存，账单上该记的 token 还是会记。

拆开讲

它到底在算什么？

大模型读文本不是一个字一个字读，而是先把文本切成小碎块，每个碎块就是一个 token（模型处理文本的最小单位）。比如"今天天气不错"可能被切成"今天""天气""不错"，也可能被切成单字，取决于模型自己的切法。切完后每个 token 对应一个数字编号，模型处理的是编号序列。token 既是模型的"最小文字单位"，也是计费的最小单位：每处理一个，算一份钱。

一句话值多少个 token？

没有固定答案，但有大致范围：一个 token 约等于 0.6 到 1.5 个汉字，或 0.75 个英文单词。常用词可能一个 token 装下，生僻字可能要占好几个 token；英文长单词也常被切成两三个。所以同一句话在不同模型里数出的 token 数可能不一样，"每百万 token"的报价只在同一家模型、同一个词表（模型认识的所有 token 的清单）下面才可以直接比较。

谁在按 token 收钱？

主要是以 API（应用程序接口，让别的软件来调用模型能力的入口）方式卖模型的平台，业内叫 MaaS（Model as a Service，模型即服务）。一次请求会产生两类 token：输入 token（你发的内容）和输出 token（它生成的回答），两者通常分开计价。聊天时输入往往比输出多，因为历史对话要一遍遍重新发；写代码、写文章时反过来，输出占大头。

为什么偏偏按 token 收钱？

因为 token 大致对应模型的干活量：处理的 token 越多，占用的计算资源越多。生成 token 的过程叫推理（用训练好的模型生成输出），是这些公司花销的大头。按 token 计费对客户直观：用得越多付得越多。相比按卡时租算力（卡时指一张 GPU 跑一小时），按 token 计费让客户不必关心背后用了多少显卡，只需关心自己用了多少内容。

再深一点

这一节写给工程，业务读者可以跳过。

具体机制：token 来自分词。模型发布时带一套固定词表（模型认识的所有 token 的清单），分词器把输入文本按词表切成 token 序列，每个 token 映射成一个整数 ID，模型处理的是 ID 序列。手册第 14 章称这一入口为"分词入口"。一次请求被手册第 15 章分成"两段负载"：输入 token 走 prefill 阶段，被模型读取并写入缓存；输出 token 走 decode 阶段，逐个生成。手册没有给出这两段各自耗时占比的数字，只指出资源画像不同，这对容量规划和报价有直接影响：输入 token 有缓存可复用，输出 token 是纯增量计算。

关键数字：手册术语基线给出的换算是 1 个 token 约等于 0.6 到 1.5 个汉字、0.75 个英文单词；行业报价单位是每百万 token（M tokens）；TPM（tokens per minute，每分钟 token 数）是衡量吞吐的常用单位，注意别和 TPS 混，按秒算差 60 倍。

和同类方案的差别：手册区分了两种计价体系，按卡时（一张 GPU 跑一小时）是算力租赁的通行单位，按 token 是推理服务的计价单位。按 token 计费把算力开销包装成"内容量"，客户不需要懂硬件，但代价是 token 数与真实计算量不是严格线性：相同的输入 token 命中前缀缓存时实际开销不同，输出 token 与输入 token 的边际开销也不同。因此跨模型直接比"每百万 token"价格没有意义，要连同词表和缓存策略一起看。手册没有给出这些差距的量化数字。

边界：同一个句子在不同模型下 token 数不同，跨模型换算只能按上面的比例粗估；token 和区块链里说的 token 是两个毫无关系的词，手册术语基线里专门标注了这点。手册没有给出特定模型的词表大小和实测 token 比例，需要拿真实文本测过才能落地。

跟我们业务什么关系

我们会在三处碰到 token：给客户报 API 价格时，它是计费单位；拿到上游模型平台账单时，它是核对对象；评估一次对话的真实开销时，它是输入变量。不懂的代价很直接，报价时算不出一次请求要花多少钱，对账时验证不了账单数字，压测时不知道并发该设多少。手册第 5 章"计量链路"的提法是，计量口径要写进合同才可执行，第 8 章"最小启动"则建议放量前先固定计量环节。我们内部各产品线当前的计量口径是否统一，素材没有覆盖，建议产品和商务各指定一人，拉一遍现有报价单和账单的计费单位，对齐后再谈优化。

你现在能做什么

  1. 拿一段 300 字左右的中文，用任一开源分词器的在线 demo 数一遍 token，把 token 数和字数都记下来。完成标志：你能说出"我的文本 X 字约等于 Y 个 token"。
  2. 把手头所有跟模型服务相关的报价单或账单翻一遍，标出每份按什么单位计费（token、字符、请求次数还是包月）。完成标志：一张清单，逐条写明产品名和计费单位。
  3. 找负责采购或合同的同事问一句：我们和上游结算时，token 的数量以谁的账单为准。完成标志：得到一句明确答复并记进笔记。

自测

第 1 题：1 个 token 严格等于 1 个汉字，对吗？

答案 不对。一个 token 约等于 0.6 到 1.5 个汉字，或 0.75 个英文单词，具体取决于模型的切分方式。

第 2 题：为什么同一句话在两个模型里数出的 token 数可能不一样？

答案 因为每个模型有自己的词表和分词器，切法不同，token 数就不同。所以跨模型比较"每百万 token"的价格没有直接意义。

第 3 题：一次 API 请求里，输入 token 和输出 token 可以按同一个价格算钱吗？

答案 通常不可以。输入和输出是两段负载，资源消耗不同，大多数 MaaS 平台对两者分开计价。

术语表与来源

术语表

  • token：模型处理文本的最小计费单位，约等于 0.6 到 1.5 个汉字或 0.75 个英文单词
  • 词表（vocabulary）：一个模型认识的所有 token 的清单，分词时按它来切
  • 分词器（tokenizer）：把文本切成 token 的工具，每个模型自带一套
  • 推理（inference）：用训练好的模型生成输出的过程
  • TPM：tokens per minute，每分钟处理的 token 数
  • 卡时：一张 GPU 运行一小时，算力租赁的计价单位
  • MaaS：Model as a Service，模型即服务，以 API 方式对外提供模型能力
