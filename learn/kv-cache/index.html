推理里的 KV Cache

AI 扫盲约 6 分钟更新于 2026-08-03

为什么你要懂这个

你在跟客户谈一套部署方案，工程给了一个数字：这台机器能同时服务多少人。你把这个数字写进方案。交付时客户把单次对话能装的内容量调大了好几倍，同时在线人数直接掉下来，客户认为我们没做到承诺。

问题不在工程算错，在于那个并发数字（同一时刻能服务多少人）本来就跟单次对话长度绑在一起，只报一个数字等于没报。不懂 KV Cache，你就不知道这两个数字必须成对出现，也就没法在谈的时候把话说严谨。

一句话说清

模型把算过的中间结果存起来重复用，生成更快，代价是占显卡内存，对话越长占得越多。

打个比方

装修的时候要量房。假设你每加一件家具，都要把整个房子从头到尾重新量一遍，加到第十件，你已经量了十遍。聪明的做法是第一次量完就记在本子上，后面每加一件只量新增的那一点，其余的翻本子。KV Cache 就是那个本子：把已经算过的结果记下来，别重算。

这个比方哪里不成立：

第一，本子多写几页几乎不占地方，KV Cache 占的显卡内存是实打实的，而且跟内容长度成正比，很快就能把一张卡吃满。这是它和普通笔记最大的区别，也是这一页真正要你记住的部分。

第二，本子写完可以复印给别人，同一时刻正在进行的每个对话通常各占一份自己的缓存，互相不能顶替。具体到某一款推理软件是否有共享机制，这一点没有确认。

拆开讲

模型生成一句话的时候，在重复算什么

大模型是一个词一个词往外吐的（这里的"词"是模型内部的最小单位，和中文的词不完全对应，不影响理解）。它吐每一个新词之前，都要回看前面已经有的全部内容，算出一组中间表示，再据此决定下一个词是什么。

关键在"全部内容"。生成第 1 个词回看 1 个，第 2 个回看 2 个，第 100 个回看 100 个。如果每次都从头重算，生成 N 个词的总计算量大致是 N 乘 N。N 是 100 的时候是一万次量级，N 是 1000 的时候就是一百万次量级，长度翻十倍，代价翻一百倍。这就是不做缓存时的成本曲线。

存下来的到底是什么

存的不是文字本身，是模型对前面每个词算出来的中间结果。这些结果一旦算出来就不会再变，因为前面的内容已经定了，后面新增什么都不影响它们。既然不变，就没有重算的理由。

缓存的名字叫 KV Cache，K 和 V 是这两组中间结果在模型内部的代号，两个字母的完整含义属于模型结构细节，这一页不展开，不影响你判断成本。有了它，生成第 N 个词时，前面 N 减 1 个的结果直接取出来用，只需要算新增的那一个。总计算量从 N 乘 N 降到 N 这个量级。

为什么省的是时间，花的是显卡内存

推理（模型对外提供服务、实际产出回答的过程）跑在显卡上，显卡上的内存叫显存，容量是固定的，插满就是那么多，不能临时借。

模型本身的参数要常驻显存，这部分是固定开销。KV Cache 是额外开销，而且它随内容长度线性增长：内容长一倍，这份缓存大一倍。你可以理解成，显存被分成两块，一块放模型，剩下的才是能装对话的空间。KV Cache 就是在剩下的这块地里跑马圈地，跑得越远，别人能站的地方越少。

上下文开长，代价具体落在哪

上下文指模型单次能同时看到的内容总量，问题加历史加资料都算在里面。上下文开得长，用户体验更好，能一次塞进整份文档。

代价是每个正在进行的对话都要占更大一份缓存。显存总量不变，单份占得多，能同时装下的份数就少，也就是同一张卡能同时服务的人变少。所以"这台机器能服务多少人"这句话，脱离上下文长度是不成立的，这是本页最容易被漏掉的一点。至于具体到某个模型某张卡上，长度和人数的换算关系是多少，需要工程实测，不能靠推断。

跟我们业务什么关系

最直接的场景是对外做部署方案测算：客户问一套设备能支撑多少人同时用，我们必须把答案写成一组条件，而不是一个数字。不懂这个，商务会在没有约束的情况下报出一个并发数，交付时对不上，返工和信任成本都由我们承担。

第二个场景在我们自己这边：内部把长文档和会议记录自动整理成材料的那条流程，输入天然很长，属于典型的长上下文任务。这类任务跑起来占显存多，和别的任务抢资源。

我们现在的做法是：涉及并发承诺的场合，上下文长度和并发数必须成对出现，由工程实测给数，不允许口头估。实测的具体数字属于内部信息，不在本页展开。

你现在能做什么

  1. 打开你手边任意一个在用的大模型服务的说明页，找到上下文长度这一项。完成标志：你能说出这个服务单次最多能装多少内容，数字写在你自己的笔记里。

  2. 在你负责的方案模板或需求文档里，加一个必填项：目标上下文长度。完成标志：今天之内文档里出现这个字段，且填了一个具体数字，或者明确写着待工程确认。

  3. 用不含术语的话把这件事讲给另一位同事听，请对方复述。完成标志：对方能自己说出"省的是时间，花的是显卡内存"这两点。

自测

第一题（判断） 用了 KV Cache 之后，模型回答得更准了。

答案

错。它只改变速度和内存占用，存的是已经算过、且不会再变的中间结果，取出来用和重算一遍结果一样，输出内容不变。

第二题（选择） 把上下文长度调大一倍，最直接的后果是： A. 回答质量提高一倍 B. 同一张卡能同时服务的人变少 C. 模型的参数变多

答案

B。每个对话占的缓存变大，显存总量没变，能同时装下的对话就变少。A 和 C 都和这件事无关。

第三题（判断） 不用 KV Cache，生成 N 个词的计算量大致是 N 乘 N；用了之后降到 N 这个量级。

答案

对。这正是这套缓存存在的理由，节省的幅度随内容变长而变大。
